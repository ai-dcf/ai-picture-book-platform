## 背景

当前页面 AI 绘画提示词的生成链路，会把 `Stage4Assets` 中角色素材的完整描述直接传给页面 prompt 生成模型。由于角色素材描述通常包含服饰、配饰、鞋子、帽子、体貌与颜色等固定造型信息，模型在生成页面 prompt 时会把这些内容再次展开，导致页面 prompt 出现大量重复的角色穿着描述。

这与当前产品流程不一致：

- 角色固定形象已经在 `Stage4Assets` 中通过基础形象图确认。
- `Stage5Pages` 中的页面 prompt 应优先通过 `#(图片N)` 引用角色参考图来继承形象一致性。
- 页面 prompt 需要更聚焦于当前页真正发生的动作、构图、场景关系、光影和临时状态变化，而不是重复角色固定造型。

## 目标

- 调整页面 AI 绘画提示词生成时使用的 prompt 规则，避免默认重复角色固定服饰与外观设定。
- 保持页面 prompt 继续通过 `#(图片N)` 机制引用 `Stage4Assets` 中的角色和场景图片。
- 将页面 prompt 的默认镜头构图设为远景/全景，以便完整展示角色和场景内容。
- 保留“只有当前页明确写出的变化才进入 prompt”的能力，避免误删有效页面信息。
- 将改动范围严格限制在页面 prompt 生成模板，不修改接口、状态结构或页面出图协议。

## 用户已确认的规则

- 角色固定形象默认由 `Stage4Assets` 生成并确认的参考图承接。
- 页面 prompt 默认不写角色固定服饰、固定配饰、固定鞋帽、固定外观和固定颜色方案。
- 只有当当前页 `visualGoal` 或用户手动编辑的 prompt 中明确出现可见变化时，才允许把这些变化写入页面 prompt。
- 未指定镜头时，页面 prompt 默认使用远景/全景构图。
- 默认构图目标是完整展示角色全身、角色之间的位置关系，以及主要场景的空间关系。
- 如果当前页明确写了近景、中景、特写、半身或局部镜头，则以当前页要求覆盖默认远景规则。
- 本次只修改“生成 AI 绘画提示词的 prompt”，不修改 `#(图片N)` 机制，不修改出图接口。

## 方案

### 1. 改动边界

- 仅修改 `src/prompts/builders/page.ts`。
- 仅调整以下两个函数：
  - `buildPagePromptGenerationSystemPrompt()`
  - `buildPagePromptGenerationUserPrompt()`
- 保持以下内容不变：
  - `src/modules/studio/application/use-cases/generate-page-prompt.ts` 的两段式生成流程不变
  - 引用识别和 `#(图片N)` 自动编号机制不变
  - 页面最终出图接口与参数结构不变

### 2. 页面 Prompt 生成链路保持不变

- 继续保留现有两段式流程：
  - 第一步：文本模型根据 system prompt 与 user prompt 生成页面主体画面描述
  - 第二步：从最终 prompt 中识别命中的角色和场景名称，并插入 `#(图片N)` 标注
- 本次不增加第三段后处理清洗逻辑，也不引入正则删除服饰词的策略。
- 这样可以把“不要展开角色固定造型”的约束尽量前置到模型输入阶段，减少脆弱的后处理规则。

### 3. System Prompt 调整

- `buildPagePromptGenerationSystemPrompt()` 需要新增明确规则，约束模型：
  - 角色基础形象由参考图片负责承接，不要重复输出固定服饰、固定配饰、固定外观或固定颜色设定
  - 只有当前页描述中明确出现的新增变化，才允许写入页面主体画面描述
  - 如果角色没有明确变化，只描述角色名称、数量、站位、朝向、动作、表情、与场景的关系
  - 未指定镜头时，默认按远景/全景构图组织画面
  - 默认优先完整展示角色全身和主要场景，避免只截取局部或半身
- 继续保留现有规则：
  - 只输出页面主体画面描述
  - 不重复项目统一风格片段
  - 使用客观、可见、可绘制的视觉语言
  - 不输出解释、标题、Markdown、模型参数或心理活动

### 4. User Prompt 调整

- `buildPagePromptGenerationUserPrompt()` 不再把角色素材完整描述原样灌入模型。
- 当前 `角色设定概览` 会暴露角色 description 中的固定服饰与外观，应该改为更克制的输入结构。
- 角色部分改为只提供：
  - 角色名称列表
  - 一条明确规则，说明角色固定形象已由参考图承接，不要复述固定造型
  - 一条明确规则，说明只有本页明确变化时才提炼变化点
- 场景部分继续提供：
  - 场景名称列表
  - 场景设定概览
- 保留页面文字、画面内容描述、项目统一风格片段、目标年龄和项目风格等输入项。
- 新增默认构图说明：
  - 若页面描述未指定镜头，则按远景/全景构图处理
  - 优先完整展示角色与场景关系

### 5. 允许与禁止的输出内容

- 页面 prompt 中允许保留的信息：
  - 角色名称、数量、站位、朝向、姿势动作、手势、眼睛和嘴巴形态
  - 角色与角色之间、角色与场景之间的空间关系
  - 场景主体、空间层次、构图、景别、视角、光线方向、色温、色调
  - 当前页明确写出的临时可见变化，例如汗珠、淋湿、背包、拿着新道具、衣物状态变化
- 页面 prompt 中默认禁止的信息：
  - 固定服饰
  - 固定配饰
  - 固定鞋帽
  - 固定体貌描述
  - 第 4 步角色图中已经确定、但当前页没有明确要求变化的设定

### 6. 变化判断规则

- “允许写入页面 prompt 的变化”必须满足两个条件：
  - 变化是可见的、可绘制的
  - 变化在当前页 `visualGoal` 或用户手动编辑的 prompt 中被明确表达
- 页面 prompt 只写变化本身，不回溯整套原始造型。
- 示例：
  - 允许：`老三 #(图片3) 额头有汗珠，握拳展示力量`
  - 不允许：`老三 #(图片3) 身穿蓝色工装短裤，系着工具腰带，额头有汗珠`

### 7. 默认构图规则

- 若当前页没有明确镜头要求，则模型默认输出远景/全景构图描述。
- 默认构图的目标是：
  - 完整展示主要角色全身
  - 展示角色之间的位置关系
  - 展示主要场景主体及其空间关系
- 只有当前页 `visualGoal` 明确写出近景、中景、特写、半身、局部等镜头要求时，才覆盖默认远景/全景规则。

### 8. 兼容性

- 由于 `generate-page-prompt.ts` 的第二阶段引用识别仍基于最终 prompt 里的名称匹配，页面 prompt 里继续保留角色名和场景名即可，不会影响 `#(图片N)` 生成。
- 页面 prompt 去掉角色固定服饰细节后，引用参考图的价值会更清晰，角色形象一致性会更多依赖图片而非文字重复描述。
- 本次不改变页面出图时 `promptUserEdited` 的优先级与现有行为。

## 涉及文件

- `src/prompts/builders/page.ts`
  - 调整页面主体描述生成的 system prompt 规则
  - 调整页面主体描述生成的 user prompt 结构

## 验收标准

- 页面 prompt 自动生成结果默认不再重复角色固定服饰、固定配饰与固定外观设定。
- 页面 prompt 中仍能正确出现角色名与场景名，并继续支持后续 `#(图片N)` 标注。
- 当页面 `visualGoal` 未指定镜头时，生成结果倾向于远景/全景构图，能够完整展示角色和场景。
- 当页面 `visualGoal` 明确写出近景、中景、特写等镜头要求时，生成结果以该页要求为准。
- 当页面 `visualGoal` 明确写出角色临时状态变化时，生成结果能保留这些变化描述。
- `generate-page-prompt.ts`、页面出图接口、引用编号机制不因本次改动产生回归。

## 风险与取舍

- 角色完整 description 不再直接提供给页面 prompt 模型后，模型对角色固定形象的文字认知会减弱，但这正符合当前由参考图承接角色形象的一致性设计。
- 场景概览仍然保留，模型可能继续吸收较多场景细节；这是可接受的，因为场景结构信息对单页构图仍有帮助。
- 默认远景/全景会提高“角色和场景完整入画”的稳定性，但某些天然适合近景的页面，如果用户没有明确写镜头，生成结果会更偏全景；这是本次设计中有意选择的默认行为。

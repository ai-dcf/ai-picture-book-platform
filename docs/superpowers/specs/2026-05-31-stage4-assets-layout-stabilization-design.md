# Stage4Assets 三栏布局稳定性修复设计

日期：2026-05-31

## 背景

在 `Stage4Assets.tsx` 引入三栏工作台布局后，页面出现了明显的 UI 错乱：主内容区高度关系异常、底部历史区与上半区互相挤压、预览区域占比过大，导致整体不稳定且与桌面端工作台预期不符。

用户确认不回退到旧版长列表，而是在保留三栏工作台方向的前提下，优先修复结构稳定性问题。

## 目标

- 保留 `Stage4Assets` 的三栏工作台方向。
- 解决重叠、遮挡、漂浮错位、空白异常和滚动冲突。
- 将三栏比例调整为 `左窄 中宽 右中`。
- 明显收窄右侧预览区，避免图片区域过大。
- 让底部历史区稳定地位于主内容区下方。

## 用户已确认的规则

- 修复策略选择：`优先修好`，不完全回退。
- 错乱问题按综合问题处理：高度、层级、列宽分配统一修。
- 修复目标是：`稳住 + 基本像原型`。
- 接受把三栏比例调得更保守。
- 用户明确指出：当前图片预览区域太大。
- 修复后的比例采用：`左窄 中宽 右中`。
- 采用 `结构修复优先`，不先追求更激进的视觉贴原型。

## 方案

### 1. 三栏比例收敛

- 重新定义三栏 grid 比例，确保：
  - 左侧列表最窄，仅承担导航
  - 中间编辑区成为主工作区
  - 右侧预览区收窄到中等宽度
- 本次不追求“大图优先到极致”，而是先保证页面稳定。

### 2. 高度与滚动关系修复

- 三栏主区域与底部历史区改为清晰的上下两层。
- 避免上半区与下半区互相争抢高度。
- 清理导致塌陷或异常拉伸的 `flex-1`、`min-h-0`、`overflow` 组合冲突。
- 减少不必要的嵌套滚动，优先保证主布局稳定。

### 3. 容器层级修复

- 保证编辑区、预览区、历史区都回到正常文档流。
- 不依赖看起来像“浮层覆盖”的容器关系来拼页面。
- 让三栏卡片和底部卡片层级清晰、边界明确。

### 4. 预览区尺寸收敛

- 缩小右侧预览列宽度。
- 控制预览图容器高度，避免其把页面重心拉偏。
- 保留右侧“预览 + 主要操作”的结构，但不再让其压制中间编辑区。

### 5. 改动边界

- 只修改 `src/components/studio/stages/Stage4Assets.tsx`
- 不改 reducer、接口、数据结构
- 不改角色生成、场景生成、历史恢复、确认流转等业务逻辑
- 不回退到旧版长列表结构
- 不新增新的复杂交互模型

## 风险与处理

- 风险：如果继续保留过多嵌套滚动容器，布局可能仍旧不稳定。
- 处理：优先收敛为更简单的主内容流和更明确的上下结构。

- 风险：右侧预览区收窄后，原先依赖大图展示的视觉效果会减弱。
- 处理：接受“保守比例优先”，先解决结构稳定，再做视觉微调。

- 风险：角色与场景两套布局实现不一致，造成一边修好一边仍旧错乱。
- 处理：两者统一按照同一套骨架和尺寸策略修复。

## 非目标

- 本次不改 `Stage4Assets` 的信息架构方向
- 本次不新增移动端适配
- 本次不顺手重做其他阶段页面
- 本次不额外增加低价值自动化测试

## 验收标准

- 页面不再出现明显重叠、遮挡、漂浮错位。
- 三栏比例符合 `左窄 中宽 右中`。
- 中间编辑区宽度明显大于右侧预览区。
- 右侧图片预览区不再显得过大。
- 底部历史区稳定出现在主内容区下方。
- 角色 tab 和场景 tab 的布局骨架保持一致。
- `Stage4Assets.tsx` 不引入新的 TypeScript 或 JSX 结构错误。

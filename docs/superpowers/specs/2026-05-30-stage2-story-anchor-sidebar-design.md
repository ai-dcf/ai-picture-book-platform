# Stage2Story 左侧目录导航设计

日期：2026-05-30

## 背景

当前 `Stage2Story.tsx` 已经同时承载“故事架构”与“分镜拆页”相关内容，页面信息密度较高。用户希望参考原型 `prototype/stitch_ai_ui_ux/1_ai_v1.0` 中的左侧目录导航形式，在 `Stage2Story` 内加入常驻目录，提升桌面大屏下的浏览与编辑效率。

## 目标

- 在 `Stage2Story.tsx` 内增加左侧目录导航。
- 目录项固定为：`故事大纲`、`角色`、`场景`、`分镜拆页`。
- 点击目录项时，右侧内容区平滑滚动到对应区块。
- 右侧滚动时，左侧目录自动跟随高亮当前区块。
- 视觉结构参考原型，但颜色、圆角、边框和交互状态沿用当前项目风格。
- 只面向电脑端大屏使用，不考虑移动端适配。

## 用户已确认的规则

- 采用推荐方案 B：仅在 `Stage2Story` 内完成“左侧导航 + 右侧内容”的重组。
- 目录项为 4 项：`故事大纲`、`角色`、`场景`、`分镜拆页`。
- 交互采用“点击跳转 + 跟随滚动高亮”。
- 视觉采用折中方案：结构贴近原型，风格跟当前项目统一。
- 目录保留“图标 + 文案”。
- 目录需要 `sticky` 吸顶。
- 只关注电脑端大屏，不考虑移动端适配。
- 左侧目录宽度采用中等宽度，约 `240-260px`。

## 方案

### 1. 页面结构

- `Stage2Story` 改为双栏布局：
  - 左侧：目录导航栏，固定宽度约 `240-260px`
  - 右侧：现有主编辑内容区
- 左侧目录栏在桌面工作台中常驻显示，使用 `sticky` 保持在可视区域内。
- 右侧内容区继续承载现有标题、操作按钮、故事编辑、角色编辑、场景编辑、分镜编辑等内容。
- 本次不抽离通用组件，改动集中在 `Stage2Story.tsx`，降低影响面。

### 2. 目录项与内容映射

目录与现有内容的映射关系如下：

- `故事大纲`：映射到当前“故事大纲”编辑区
- `角色`：映射到当前“角色设定”编辑区
- `场景`：映射到当前“场景清单”编辑区
- `分镜拆页`：映射到当前“分镜拆页”总区块，包含封面设置、检查结果和分页内容

说明：

- 本次不新增“故事架构”总览项。
- 本次不拆分“封面设置”为单独目录项。
- 本次不恢复原型中的“情感曲线”目录项，因为当前页面内容中不存在独立对应区块。

### 3. 导航交互

- 点击目录项时，页面滚动到对应 section。
- 滚动行为使用平滑滚动，避免突兀跳转。
- 右侧内容滚动时，目录自动高亮当前 section。
- 高亮切换不以“刚进入视口”作为唯一条件，而是基于顶部可视区域附近的稳定阈值，避免短区块抖动。
- 当前高亮项使用更明显的底色、文字色和轻边框；未高亮项保留 hover 状态。

推荐实现：

- 使用 `ref + scrollIntoView()` 处理点击跳转。
- 使用 `IntersectionObserver` 处理 section 可见性检测与高亮切换。
- 若当前容器结构不适合 observer，则回退为监听滚动位置并按 section 顶部位置计算当前项。

### 4. 视觉风格

- 目录结构参考原型：纵向排列、图标在左、文案在右、当前项高亮。
- 目录颜色不照搬原型的深色系统，而是使用项目现有的 `card / muted / primary / border` 体系。
- 圆角、内边距、文字大小、hover 效果遵循现有工作台 UI 语言，避免形成独立风格岛。
- 目录视觉重点服务导航清晰度，不增加额外统计信息、计数器或复杂层级。

### 5. 实现边界

- 只修改 `src/components/studio/stages/Stage2Story.tsx`。
- 不改动故事生成、检查、修复、保存、确认进入下一阶段等业务逻辑。
- 不改动 `story`、`storyboard`、`cover`、`stageStatuses` 等业务数据结构。
- 允许新增页面级 UI 状态，例如：
  - 当前高亮目录项
  - section 的 DOM 引用
  - 滚动观察状态

## 风险与处理

- 风险：`Stage2Story` 当前内容较长，滚动容器层级较深，可能导致 section 高亮不稳定。
- 处理：优先明确单一主滚动容器，只在该容器内做 section 观察。

- 风险：部分 section 高度较短，滚动到边界时目录项可能频繁跳变。
- 处理：通过顶部偏移和阈值配置稳定高亮切换。

- 风险：改动页面布局后，现有按钮区和长表单区的留白关系可能失衡。
- 处理：在双栏布局中统一右侧内容宽度与段落间距，只调整容器组织，不改内部控件行为。

## 非目标

- 本次不为 `Stage4Assets`、`Stage5Pages`、`Stage6Finalize` 增加同类目录。
- 本次不抽通用锚点侧栏组件。
- 本次不考虑移动端、平板端或自适应折叠导航。
- 本次不改动 `TopBar`、全局阶段进度或其他页面结构。

## 验收标准

- `Stage2Story` 在桌面端显示左侧目录与右侧内容双栏布局。
- 左侧目录包含且仅包含：`故事大纲`、`角色`、`场景`、`分镜拆页`。
- 点击目录项时，可以平滑滚动到对应内容区块。
- 滚动右侧内容时，目录会自动高亮当前区块。
- 页面原有生成、检查、修复、保存与确认逻辑保持可用。
- `Stage2Story.tsx` 不引入新的 TypeScript 或 JSX 结构错误。

# 首页沉浸式工作台重设计

日期：2026-05-31

## 背景

当前首页 `src/app/components/HeroPage.tsx` 采用“品牌标题 + 项目卡片墙”的展示方式，更接近作品入口页；而 `src/components/studio/stages/Stage1Init.tsx` 则承担了新建项目的主题输入、参数选择、故事概要优化和进入创作流程的职责。

用户希望参考 `prototype/stitch_ai_ui_ux/ai_5` 的原型结构，将“首页入口”和“第一阶段建项”合并为一个沉浸式工作台：

- 首页直接成为工作台，而不是营销式欢迎页
- 左侧为项目列表，便于快速续作和管理
- 右侧为新建项目工作台，默认优先服务“立即开始创作”
- `Stage1Init.tsx` 不再作为独立首屏入口存在

## 目标

- 将 `/` 首页重做为“左侧项目列表 + 右侧创作画布”的双栏工作台
- 参考原型的深色沉浸式氛围和桌面式布局，但保留当前项目的绘本气质
- 吸收 `Stage1Init.tsx` 的核心能力到首页右侧工作台中
- 保留 `/studio` 作为项目创建后的正式创作空间
- 让首页同时支持“新建项目”和“继续已有项目”

## 用户已确认的规则

- 首页入口采用“首页即工作台”
- 总体布局采用 `方案 A：双栏固定工作台`
- 左侧项目列表风格采用“折中”，兼顾管理效率和沉浸感
- 右侧工作台默认采用“新建优先”
- 不启用浏览器视觉辅助，设计沟通采用纯文字
- 不再保留 `Stage1Init.tsx` 作为独立首屏页面
- 从首页创建项目后，直接进入 `Stage2Story.tsx`
- Studio 进度条去掉“项目初始化”，仅保留后续四个创作阶段

## 方案

### 1. 页面总体结构

首页从当前的单页卡片墙重组为固定双栏工作台：

- 顶部：全站工作台顶栏
- 左侧：项目轨道区
- 右侧：新建项目主画布

布局原则：

- 左侧承担“找项目、切项目、建新项目”的入口职责
- 右侧承担“输入故事、选择参数、优化概要、开始创作”的主任务
- 首页首屏不再出现大面积营销标题和空洞品牌宣言
- 右侧在视觉上比左侧更重，确保“新建优先”

### 2. 顶栏

保留当前首页已有的品牌和账号能力，但从“站点导航栏”调整为“工作台顶栏”：

- 左侧保留品牌入口 `AI 绘本工作室`
- 右侧保留登录、头像菜单、设置等能力
- 顶栏使用更轻的玻璃感或半透明分层，贴近原型沉浸氛围
- 不在本次新增复杂全局导航项

顶栏目标是“稳定框架”，而不是继续承担首页主视觉。

### 3. 左侧项目轨道

左侧区域重构为固定宽度项目列表，参考原型中的 side rail：

- 顶部为搜索框
- 中间按“最近 / 昨天 / 更早之前”等时间维度分组展示项目
- 底部提供明显的 `新建项目` 按钮

项目项采用“折中风格”：

- 以列表为主，优先保证扫描效率
- 在列表项中保留轻量封面预览、状态标签、更新时间等信息
- 当前选中项高亮，形成“正在续作的项目”感知
- hover 或聚焦时显示更多操作入口，例如删除

左侧不承担复杂筛选和批量管理，避免首页演变成纯后台管理页。

### 4. 右侧新建工作台

右侧区域吸收 `Stage1Init.tsx` 的建项职责，并参考原型形成沉浸式创作入口：

- 顶部欢迎语收敛为工作台语气，例如“今天想创作什么样的绘本？”
- 主体是一张大输入卡，输入绘本主题、情节或故事概要
- 参数区保留 `目标年龄 / 页数 / 风格`
- 保留 `妙笔生花` 一键优化入口
- 保留主按钮，用于开始创作并进入 `/studio`

视觉原则：

- 右侧使用更强的背景层次、柔和光斑、渐变和玻璃卡片
- 文本输入区是第一交互重心
- 参数区和动作区围绕输入卡组织，而不是散落为多个独立块

### 5. 首页与 Stage1 的职责合并

`Stage1Init.tsx` 的职责被拆分后迁移到首页右侧工作台：

- `绘本主题与故事概要` 输入迁移到首页大输入卡
- `目标受众 / 绘本页数 / 画卷风格` 参数迁移到首页参数区
- `妙笔生花` 逻辑迁移到首页右侧动作区
- `落笔成卷` 的建项与跳转行为迁移到首页主按钮

结果：

- 首页负责“创建项目入口”
- `/studio` 负责“正式创作过程”
- `Stage1Init.tsx` 不再作为首阶段页面渲染

### 6. 首页与 Studio 的关系

首页和 `/studio` 之间明确职责边界：

- `/`：负责新建项目和打开已有项目
- `/studio`：负责故事生成、素材设定、逐页生成和定稿等后续流程
- 首页创建项目后，`/studio` 首屏直接承接 `Stage2Story.tsx`

进入方式：

- 从首页右侧创建新项目后，跳转 `/studio?projectId=xxx`
- 从左侧点击已有项目后，直接跳转 `/studio?projectId=xxx`

`/studio` 不再把“起笔构思”当成默认首屏，而是承接首页已完成的建项结果，并直接从故事架构阶段继续。

### 7. 组件拆分

本次推荐的组件组织方式如下：

- `HeroPage.tsx`
  - 调整为首页工作台容器
- 新增 `HomeProjectRail`
  - 承载项目搜索、分组列表、新建按钮、项目项渲染
- 新增 `HomeCreationWorkbench`
  - 承载故事输入、参数选择、优化、创建动作
- 可新增局部子组件
  - `ProjectRailItem`
  - `WorkbenchIdeaInput`
  - `WorkbenchQuickTags`

原则：

- 首页工作台的展示结构与 `StudioPage` 解耦
- 不把首页直接做成 `Stage1Init` 的简单外壳
- 允许抽出 `Stage1Init` 中的可复用逻辑，但不要复制粘贴整块 UI

### 8. 数据流

首页右侧新建流程：

1. 用户在右侧输入故事概要
2. 用户调整目标年龄、页数和风格
3. 点击 `妙笔生花` 时，调用 `useStudioGenerate().generateStoryPack(projectInfo, userIdea)`
4. 若返回 `story.storyOutline`，回填到输入框
5. 点击 `开始创作` 时，创建或初始化项目数据
6. 保存草稿后跳转 `/studio?projectId=xxx`
7. `/studio` 加载后直接进入 `Stage2Story.tsx`

首页左侧续作流程：

1. 加载 `useProjectHistory()` 返回的历史项目
2. 以分组列表形式展示
3. 点击项目项时跳转 `/studio?projectId=projectId`
4. 点击删除时沿用当前删除逻辑

关键边界：

- 首页右侧使用独立本地表单状态，不直接依赖 `Stage1Init` 的页面态
- 如需复用建项逻辑，应抽成共享函数或首页级 hook，而不是让首页依赖 `useStudio()` 的阶段页面上下文

### 9. 交互细节

首页右侧工作台补充以下交互：

- 未输入主题时，主按钮禁用
- 优化中时，优化按钮进入 loading
- 创建中时，主按钮进入 loading，并禁止重复提交
- 创建失败时，在右侧工作台顶部展示局部错误提示
- 点击左侧 `新建项目` 时，右侧表单重置为空白新建态

首页左侧补充以下交互：

- 搜索按标题关键字过滤项目
- 没有匹配结果时展示空结果提示
- 项目为空时保留空态，但右侧仍可直接新建
- 在桌面端左侧固定；在移动端改为抽屉或折叠列表

### 10. 视觉语言

本次首页视觉方向采用“沉浸式创作工作台”，而不是纯 SaaS 表格后台：

- 背景使用深浅叠加的渐变和柔和光斑
- 右侧主卡使用更高权重的容器层级
- 左侧项目轨道采用低对比列表层级，避免抢走首页主任务
- 保留当前项目的 `font-display`、暖色渐变与绘本气质
- 参考原型的深色桌面感，但不照搬其全部配色系统

最终观感应更像“创作桌面”，而不是“项目宫格页”。

### 11. 响应式策略

桌面端采用固定双栏结构：

- 左侧固定宽度项目轨道
- 右侧自适应主画布

移动端策略：

- 左侧项目轨道收起为抽屉或底部入口
- 右侧工作台改为单列纵向堆叠
- 不强求完全复刻桌面端沉浸感

本次优化重点是桌面端首页体验。

### 12. 保留逻辑

本次保留以下已有能力：

- `useProjectHistory()` 的项目列表和删除逻辑
- `useStudioGenerate()` 中的 `generateStoryPack` 能力
- 登录、头像菜单、设置跳转
- `/studio?projectId=...` 的项目打开方式

本次不要求改动以下底层能力：

- 后端接口结构
- 项目持久化数据模型
- `Stage2` 及后续阶段的业务逻辑
- 图片生成、素材设定、导出等后续流程

## 实现边界

- 首页主改文件为 `src/app/components/HeroPage.tsx`
- 允许新增首页专用子组件
- `src/app/page.tsx` 仍然只作为首页路由入口
- `src/modules/studio/presentation/components/StudioPage.tsx` 需要调整首阶段承接方式
- `src/components/studio/stages/Stage1Init.tsx` 不再继续作为用户首屏入口，可保留文件一段时间用于迁移过渡
- `src/components/studio/ProjectProgress.tsx` 需要调整步骤展示，移除“项目初始化”
- 不新增后端接口
- 不修改项目持久化 schema
- 不顺手重做 `/studio` 其他阶段页面

## 风险与处理

### 风险 1：首页直接复用 `Stage1Init` 会导致上下文耦合

处理：

- 不直接把 `Stage1Init` 挂到首页
- 抽离可复用逻辑，首页独立渲染工作台 UI
- 将页面态和阶段态边界分开

### 风险 2：首页建项后，`/studio` 仍可能回到第一阶段

处理：

- 明确调整 `StudioPage` 的入口承接逻辑
- 新建项目成功后直接以 `Stage2Story.tsx` 作为进入页
- 加载已有项目时根据项目状态进入正确阶段

### 风险 5：去掉“项目初始化”后，进度条文案和阶段编号可能与内部状态不一致

处理：

- 将 Studio 对外展示步骤改为四段式
- 内部如仍保留旧阶段编号，仅作为兼容迁移使用，不再暴露给用户
- 首页创建项目时直接把项目送入故事架构阶段，避免用户感知到旧首阶段

### 风险 3：左侧项目列表如果信息过多，会削弱沉浸感

处理：

- 采用“折中”方案，只保留标题、状态、时间和轻量封面
- 不加入过多管理字段
- 把视觉权重始终留给右侧工作台

### 风险 4：首页同时承担“新建”和“续作”，容易产生信息竞争

处理：

- 右侧保持高优先级的大输入卡
- 左侧控制宽度和视觉对比
- 让“新建优先”成为明确的视觉主线

## 非目标

- 本次不重做 `/studio` 中的 `Stage2Story`、`Stage4Assets`、`Stage5Pages`、`Stage6Finalize`
- 本次不新增首页模板市场、推荐内容流或社区内容
- 本次不扩展多项目批量操作
- 本次不新增后端搜索接口
- 本次不增加低价值自动化测试
- 本次不要求彻底删除 `Stage1Init.tsx` 文件本身，只要求不再作为首屏工作流入口
- 本次不要求同步重构 Studio 内部所有阶段枚举和底层状态编号，只要求用户可见流程改为四阶段

## 验收标准

- `/` 首页改为固定双栏工作台结构，形成“左侧项目列表 + 右侧创作入口”
- 左侧支持项目搜索、分组展示、打开项目、删除项目和新建入口
- 右侧吸收原 `Stage1Init.tsx` 的输入、参数、优化和建项职责
- 点击 `妙笔生花` 后可回填优化后的故事概要
- 点击首页主按钮后可以成功创建项目并跳转 `/studio?projectId=...`
- 从首页创建项目后，`/studio` 首屏直接进入 `Stage2Story.tsx`
- Studio 进度条不再显示“项目初始化”，只显示以下四段：
  - `故事架构与分镜拆页`
  - `素材设定`
  - `逐页生成`
  - `编辑定稿与导出`
- 首页在项目为空、搜索为空、优化失败、创建失败时都具备合理状态
- 不引入新的 TypeScript、JSX 或明显路由回归问题

# 绘本提示词系统优化设计

## 背景

当前项目已经将分散的提示词与增强器逻辑收拢到 `src/prompts/`，并形成了故事生成、分镜生成、资产生成、页面生成四条主要链路：

1. `generateStory()` 负责根据项目参数生成故事 JSON。
2. `generateStoryboard()` 负责将故事拆解为逐页分镜。
3. `generateAssetImage()` 负责生成角色/场景资产图，作为视觉锚点。
4. `generatePageImage()` 负责结合分镜、资产与参考图生成页面图像。

当前系统已经具备以下基础能力：

- 图片接口支持 `prompt / negativePrompt / size / quality / style / seed / images`。
- 页面与资产生成已支持稳定 `seed`、负向提示词和参考图透传。
- 项目存在明确的业务枚举约束：年龄段、风格、页数、画幅皆为有限集合。

但现有提示词系统仍然存在结构松散、规则分散、扩展成本高的问题，尤其在以下方面表现明显：

- 年龄段仅作为标签使用，没有转化为视觉复杂度规则。
- 风格枚举缺乏对应的系统性视觉规范。
- 角色和场景连续性约束主要依赖自然语言描述，缺少结构化控制。
- 合规控制主要依赖负面词，缺乏儿童绘本业务规则层。
- 缺少一套可复用的真实模型回归验证机制。

本设计旨在在不破坏现有工作流和类型体系的前提下，完成面向儿童绘本生成场景的提示词系统化升级。

## 目标

- 将现有提示词逻辑重构为统一的分层规则系统，适配当前项目技术框架。
- 让故事、分镜、资产、页面四条链路共享一套年龄、风格、连续性、合规规则。
- 为绘本生成提供更强的画面一致性、风格还原度和合规稳定性。
- 提供可扩展的自定义参数位，支持题材、教育目标、文化语气等扩展需求。
- 在测试环境中使用真实模型完成 5 组连续绘本样例验证，并输出结构化报告。

## 非目标

- 不修改当前核心工作流顺序，仍保持 Story -> Storyboard -> Assets -> Pages。
- 不引入模型微调、LoRA、Embedding、IP Adapter 等超出当前项目能力边界的方案。
- 不强制修改现有 `ProjectInfo` 类型定义；新增扩展能力以可选参数位为主。
- 不在本次设计中扩展前端复杂配置面板；前端接入以兼容当前流程为优先。

## 当前约束

### 技术约束

- 图片生成当前基于 OpenAI-compatible 策略，主模型能力围绕 `doubao-seedream-5.0-lite`。
- 图片接口支持参考图、负向提示词、seed，但不支持模型级跨页记忆。
- 连续性控制只能通过工程层的规则约束、参考图与稳定参数实现。
- 当前业务层暴露的页面画幅仅有：
  - `3:4`
  - `9:16`
  - `16:9`
  - `1:1`
- 当前页面 size 映射为：
  - `3:4 -> 768x1024`
  - `9:16 -> 768x1366`
  - `16:9 -> 1366x768`
  - `1:1 -> 1024x1024`

### 业务约束

- 目标年龄段：
  - `0-3`
  - `3-6`
  - `6-9`
  - `9-12`
  - `auto`
- 画面风格：
  - `水彩温暖风`
  - `蜡笔童趣风`
  - `剪纸拼贴风`
  - `日系清新风`
  - `素描淡彩风`
  - `波普大胆风`
  - `水墨东方风`
  - `极简线条风`
  - `auto`
- 页数：
  - `8 / 12 / 16 / 24 / 32 / auto`
- 当前业务尚未原生提供题材字段，但存在明确的题材需求：
  - 原创童话
  - 经典改编
  - 科普启蒙

### 内容与审美约束

- 目标用户为儿童及亲子阅读场景，必须保证适龄、安全、温和、易理解。
- 画面应适配儿童视觉发育规律，避免高攻击性、过度刺激、恐怖或复杂噪声过载。
- 页面需要考虑后期配文，因此提示词必须明确留白区域和禁止出字规则。

## 核心问题拆解

### 1. 年龄规则缺失

现有系统仅在文本中标记“适合某年龄段”，并未将年龄映射为：

- 画面复杂度
- 单页焦点数量
- 背景信息密度
- 色彩刺激程度
- 构图稳定性
- 文本安全区大小

### 2. 风格规则缺失

现有风格为枚举名，而非完整视觉规范。缺少：

- 色彩体系
- 光影倾向
- 质感描述
- 线条语言
- 构图偏好
- 禁止项

### 3. 连续性控制偏弱

虽然已有参考图和 `Continuity` 文本，但缺少结构化的：

- 角色特征锁定规则
- 场景衔接规则
- 道具状态连续规则
- 分镜级跨页衔接逻辑

### 4. 合规规则偏弱

当前主要依赖负向提示词，缺少儿童绘本业务层面的正向和负向规范，例如：

- 恐怖感阈值
- 暴力表现阈值
- 成人化姿态与服饰限制
- 文化表达稳妥性
- 科普题材的误导风险控制

### 5. 缺少验证闭环

当前缺少面向绘本提示词系统的回归验证机制，无法系统评估：

- 角色是否漂移
- 风格是否稳定
- 合规是否通过
- 哪个规则块引起了效果变化

## 设计方案

### 总体思路

采用“分层规则 + 场景 builder + 模板文案 + 测试执行器”的结构，在不改变当前业务主流程的前提下，重构 `src/prompts/`。

推荐目录结构如下：

```text
src/prompts/
  index.ts
  builders/
    story.ts
    storyboard.ts
    asset.ts
    page.ts
  specs/
    age-spec.ts
    style-spec.ts
    genre-spec.ts
    continuity-spec.ts
    compliance-spec.ts
    model-spec.ts
  templates/
    story-system.md
    story-user.md
    storyboard-system.md
    storyboard-user.md
    asset.md
    page.md
  testing/
    prompt-evaluator.ts
    sample-cases.ts
```

### 四层主模块 + 一层扩展模块

#### 基础设定层 Base Setup

职责：

- 定义绘本“是什么”
- 决定受众、叙事目标与题材意图

应覆盖：

- 标题
- 目标年龄
- 风格
- 画幅
- 页数
- 题材类型
- 叙事基调
- 教育目标/情感目标
- 用户额外要求

此层主要影响故事与分镜，同时为资产和页面提供高层语义背景。

#### 视觉规范层 Visual Spec

职责：

- 将“年龄 + 风格 + 画幅”转换为可执行视觉规则

应覆盖：

- 色彩规范
- 光影规范
- 线条与材质规范
- 构图偏好
- 背景复杂度
- 主体焦点数量
- 镜头语言
- 文本安全区

年龄与风格的交叉作用在此层体现：

- `0-3` 低复杂度、大轮廓、背景弱化
- `3-6` 温暖、动作明确、情绪外显
- `6-9` 增加空间层次和探索感
- `9-12` 允许更强叙事密度和象征性

#### 连续性控制层 Continuity Control

职责：

- 保证“这是一本书”，而不是一组散图

应覆盖：

- 角色外观锁定
- 服饰主色锁定
- 配件锁定
- 年龄外观稳定
- 场景空间延续
- 相邻页镜头衔接
- 关键道具状态连续
- 分镜到页面的跨页传递

此层不仅用于页面提示词，也应回灌到分镜生成，让 `visualGoal` 自带连续性意识。

#### 合规校验层 Compliance Guard

职责：

- 保证内容适龄、稳妥、符合儿童绘本业务要求

应覆盖：

- 禁止恐怖、血腥、惊吓、成人化表达
- 禁止不适龄姿态、服饰、表情
- 禁止文化表达失当和符号误用
- 禁止科普类误导性画面
- 禁止文字、水印、logo、边框、签名、UI

此层既输出正向指令，也输出负向限制，不仅依赖 `negativePrompt`。

#### 自定义扩展层 Custom Params

职责：

- 在不破坏当前类型结构的前提下支持未来扩展

设计原则：

- 作为 builder 的可选参数存在
- 不强制改动 `ProjectInfo`
- 未传入时完全走默认策略

支持的典型扩展项：

- `genre`
- `educationalGoal`
- `culturalTone`
- `colorOverride`
- `safetyLevel`
- `adaptationPolicy`
- `extraVisualRules`

## 关键数据结构设计

建议在 prompt 层内部引入统一上下文结构，由当前 `ProjectInfo` 映射生成：

```ts
type PromptContext = {
  title: string;
  targetAge: TargetAge;
  artStyle: ArtStyle;
  aspectRatio: AspectRatio;
  pageCount: PageCount;
  genre?: "原创童话" | "经典改编" | "科普启蒙";
  tone?: string;
  educationalGoal?: string;
  customRequirements?: string[];
};
```

页面与资产 builder 应支持可选扩展参数对象：

```ts
type PromptCustomParams = {
  genre?: string;
  educationalGoal?: string;
  culturalTone?: string;
  colorOverride?: string;
  safetyLevel?: "normal" | "strict";
  adaptationPolicy?: string;
  extraVisualRules?: string[];
};
```

## 各生成链路的接入策略

### 故事生成

接入层：

- 基础设定层
- 合规校验层
- 题材规则

目标：

- 让故事输出更适龄
- 让故事天然适应题材目标
- 为后续分镜提供更稳定的故事骨架

### 分镜生成

接入层：

- 基础设定层
- 视觉规范层
- 连续性控制层
- 合规校验层

目标：

- 让 `visualGoal` 成为可直接指导图片生成的规格块
- 让相邻页之间存在明确衔接意识

### 资产生成

接入层：

- 基础设定层
- 视觉规范层
- 连续性控制层
- 合规校验层

目标：

- 将资产图升级为可靠的视觉锚点
- 明确角色固定特征和场景基准信息

### 页面生成

接入层：

- 基础设定层
- 视觉规范层
- 连续性控制层
- 合规校验层
- 模型参数层
- 自定义扩展层

目标：

- 收束所有约束，确保实际生成图的稳定性和业务适用性

## 模型参数策略

在当前工程能力边界下，模型参数层应明确以下策略：

- 继续保留 `negativePrompt`
- 继续保留稳定 `seed`
- 页面与资产使用固定映射后的 `size`
- 当存在已确认资产图时优先注入参考图
- 不依赖未接入的模型特性

页面与资产的默认负向约束应进一步整理为儿童绘本业务专用版本，而不是简单通用绘画负面词堆叠。

## 测试与验证设计

### 验证目标

使用真实模型生成 5 组绘本连续内容，对以下三项指标进行评估：

- 画面一致性
- 风格还原度
- 内容合规性

### 测试集设计

共 5 组样例，每组至少 4 页连续页面，并覆盖不同边界：

1. 原创童话 + `3-6` + `水彩温暖风` + `16:9`
2. 科普启蒙 + `6-9` + `极简线条风` + `3:4`
3. 经典改编 + `6-9` + `水墨东方风` + `16:9`
4. 冒险成长 + `9-12` + `日系清新风` + `9:16`
5. 低幼认知启蒙 + `0-3` + `蜡笔童趣风` + `1:1`

### 指标定义

#### 画面一致性

评分维度：

- 角色一致性
- 场景连续性
- 镜头连续性
- 道具状态一致性

每项 1-5 分，输出均分与异常说明。

#### 风格还原度

评分维度：

- 风格匹配度
- 色彩匹配度
- 质感匹配度
- 构图匹配度

每项 1-5 分，输出均分与风格漂移说明。

#### 内容合规性

二值通过项：

- 是否出现文字/水印/logo/UI
- 是否出现恐怖、血腥、惊吓内容
- 是否有不适龄表达
- 是否有文化表达不当
- 是否与题材目标严重偏离

### 验证执行器

在 `src/prompts/testing/` 中实现测试执行器，用于：

1. 读取 5 组测试样例
2. 顺序调用故事、分镜、资产、页面生成链路
3. 保存输入参数、最终 prompt、模型参数和生成结果
4. 输出结构化报告

### 验证产物

最终需要输出三类结果：

1. 标准化绘本提示词模板
2. 测试样例与评分结果清单
3. 使用说明文档

## 交付物

本次设计完成后，最终实现阶段需要交付：

- 分层后的 prompt builder 结构
- 年龄/风格/题材/连续性/合规模块
- 真实模型测试执行器
- 标准提示词模板
- 使用说明文档
- 5 组真实验证结果报告

## 风险与缓解措施

### 风险 1：真实模型波动

说明：

- 即使固定 seed，参考图链路下仍可能有轻微波动

缓解：

- 用趋势评估而非像素级一致性
- 保留 prompt、seed、参考图输入记录，便于复跑

### 风险 2：验证成本较高

说明：

- 5 组案例至少涉及资产与 20 页连续页面生成

缓解：

- 先保证最小完整样例集
- 将测试执行器设计为可复用，便于后续回归

### 风险 3：风格还原度存在主观性

说明：

- 单纯人工看图容易标准漂移

缓解：

- 在设计中提前固化评分维度和阈值

### 风险 4：题材参数尚未前端化

说明：

- 当前题材更多通过扩展参数位注入，而非原生前端字段

缓解：

- 初期先在 builder 支持扩展参数
- 未来如需产品化，再逐步接入 UI

## 分阶段实施建议

### 第一阶段：结构重构

- 拆分 `src/prompts/index.ts`
- 新增 `builders / specs / templates / testing`
- 引入统一上下文与扩展参数位

### 第二阶段：规则接入

- 接入年龄规则
- 接入风格规则
- 接入连续性规则
- 接入合规规则

### 第三阶段：测试落地

- 构造 5 组样例
- 实现执行器
- 输出报告

### 第四阶段：模板定稿

- 根据验证结果调整提示词
- 输出标准模板与使用文档

## 验收标准

- 不破坏当前 Story -> Storyboard -> Assets -> Pages 工作流
- 提示词系统完成分层重构
- 四条链路均接入统一规则体系
- 支持自定义参数位
- 完成 5 组真实模型验证
- 输出标准模板、报告和说明文档

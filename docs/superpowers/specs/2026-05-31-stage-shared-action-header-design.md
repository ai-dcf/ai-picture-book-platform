# Stage 统一顶部操作头部组件设计

日期：2026-05-31

## 背景

当前 `Stage2Story.tsx`、`Stage4Assets.tsx`、`Stage5Pages.tsx` 的顶部操作区不统一。用户希望参考 `prototype/stitch_ai_ui_ux/3_ai_v1.1/screen.png` 的结构，将主操作按钮放到页面右上角，并在多个阶段页面中保持一致体验。

同时，用户明确提出：

- 三个页面都需要做类似改动
- 按钮文案统一为 `重新生成`
- 三个页面都保留 `下一步`
- `Stage4Assets` 与 `Stage5Pages` 额外增加 `生成全部图片`
- 建议将头部抽成共享组件，而不是在各页面重复实现

## 目标

- 抽取一个共享的顶部操作头部组件
- 统一三个 stage 页面的标题区与右上角按钮区布局
- 让按钮区在视觉上接近原型中的“阶段栏右侧操作”
- 保持各页面已有业务逻辑不变，只重组顶部操作承载方式

## 作用范围

本次接入范围仅包括：

- `src/components/studio/stages/Stage2Story.tsx`
- `src/components/studio/stages/Stage4Assets.tsx`
- `src/components/studio/stages/Stage5Pages.tsx`

本次不包含：

- `Stage6Finalize.tsx`
- 更上层页面外壳或全局阶段栏
- reducer、接口、数据结构改动

## 设计结论

### 1. 组件层级

组件放在更通用的共享组件层，而不是只放在 stage 层私有目录。

原因：

- 后续其他页面也可能复用同样的头部布局
- 统一视觉改动时只需维护一处
- 不把组件绑定到某个具体 stage 的语义里

### 2. 组件职责

组件采用“半业务型 + 扩展插槽”的设计。

固定负责：

- 左侧标题
- 左侧说明文案
- 右侧按钮布局
- 标准按钮顺序与主次样式

页面传入：

- 标题
- 说明
- `重新生成` 的点击事件与禁用态
- `下一步` 的点击事件与禁用态
- 可选扩展按钮 `extraActions`

### 3. 按钮结构

默认固定两颗按钮：

- `重新生成`
- `下一步`

通过扩展位支持插入额外按钮：

- `生成全部图片`

按钮顺序固定为：

1. `重新生成`
2. `extraActions`
3. `下一步`

这样可保证三个页面的操作区顺序一致，同时兼容页面差异。

### 4. 页面映射

#### Stage2Story

显示按钮：

- `重新生成`
- `下一步`

不显示：

- `生成全部图片`

#### Stage4Assets

显示按钮：

- `重新生成`
- `生成全部图片`
- `下一步`

#### Stage5Pages

显示按钮：

- `重新生成`
- `生成全部图片`
- `下一步`

## 行为规则

- 按钮在三个页面里都始终显示
- 条件不满足时，使用禁用态，而不是隐藏
- 按钮文案不做页面差异化，统一保持：
  - `重新生成`
  - `生成全部图片`
  - `下一步`
- 本次不增加 tooltip、辅助说明或隐藏扩展文案

## 视觉策略

- 头部布局采用“左侧标题说明，右侧主操作”的固定模式
- 视觉参考原型，但不直接改全局顶部阶段栏
- 组件实际挂载在各 stage 页面内容区顶部
- 通过统一的间距、按钮尺寸、圆角和主次关系，营造接近原型的右上角操作感受

## 建议接口

建议组件提供以下输入能力：

- `title: string`
- `description?: string`
- `onRegenerate: () => void`
- `onNext: () => void`
- `regenerateDisabled?: boolean`
- `nextDisabled?: boolean`
- `regenerating?: boolean`
- `proceeding?: boolean`
- `extraActions?: React.ReactNode`

说明：

- `extraActions` 用于在 `重新生成` 和 `下一步` 中间插入按钮
- 组件本身不感知页面业务含义，只负责标准化操作区承载

## 接入策略

- `Stage2Story` 将现有头部标题和流程按钮迁移到新组件
- `Stage4Assets` 将顶部说明与底部主流程按钮能力上提到新组件
- `Stage5Pages` 同样改为使用统一头部承载主操作
- 页面内部原有业务逻辑函数继续保留，不改实现语义，只改接入位置

## 风险与处理

### 风险 1：各页面已有按钮逻辑不一致

处理：

- 组件只统一承载方式，不统一内部业务实现
- 各页面继续传入自己的点击回调和禁用条件

### 风险 2：Stage4/5 多一个按钮后宽度不一致

处理：

- 采用 `extraActions` 插槽模式，而不是硬编码所有按钮
- 统一按钮尺寸与间距，保持整体秩序

### 风险 3：顶部区域重组后与现有内容间距不自然

处理：

- 三个页面统一采用同一套头部下边距和内容起始间距
- 接入实现时按页面现状做最小必要调整

## 非目标

- 本次不改全局 shell
- 本次不改移动端策略
- 本次不顺手重做其他阶段页面
- 本次不新增复杂按钮配置系统

## 验收标准

- 三个页面都使用统一的共享头部组件
- 三个页面的右上角操作区样式保持一致
- `Stage2Story` 显示 `重新生成 + 下一步`
- `Stage4Assets`、`Stage5Pages` 显示 `重新生成 + 生成全部图片 + 下一步`
- 按钮在条件不满足时置灰禁用，不隐藏
- 不引入新的 TypeScript、JSX 或布局结构错误

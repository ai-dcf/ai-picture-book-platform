# Stage5Pages 中间提示词工作台与右侧预览区重设计

日期：2026-05-31

## 背景

当前 `Stage5Pages.tsx` 已具备逐页生成所需的核心能力，包括页面切换、文本编辑、画面描述、AI 绘画提示词生成、图片生成、右侧预览和进入编辑页。

但从 UI 观感上看，中间区域仍偏向“长表单”，右侧区域则更像“功能拼接侧栏”，存在以下问题：

- 中间区字段按顺序平铺，缺少明确的工作台层级
- `AI 绘画提示词` 虽然是核心任务，但视觉权重不够高
- `引用角色` 和 `引用场景` 分散在长表单底部，页面长度偏长
- 右侧预览区以操作块为主，大图预览的存在感不足
- “历史记录”没有稳定的 UI 承载位置，难以形成版本浏览心智

用户希望参考提供的设计稿，对 `Stage5Pages` 的中间提示词区域，以及最右侧的图片预览和历史记录区域做一次中度 UI 重设计。

## 目标

- 将中间区域从“长表单”重组为“卡片式工作台”。
- 强化 `AI 绘画提示词` 在中间区的视觉中心地位。
- 将 `引用角色` 与 `引用场景` 收敛为统一的素材引用卡片。
- 将右侧区域调整为“预览优先”的结构，大图成为第一视觉焦点。
- 为“历史记录”预留明确的 UI 骨架，但本次不扩展底层数据结构。
- 保留现有逐页生成、提示词生成、出图、预览弹窗、进入编辑页等逻辑。

## 用户已确认的规则

- 沟通方式采用中文、提问加选择方式。
- 本次不启用可视化辅助。
- 改版力度选择为“中度改版”。
- 右侧区域采用“预览优先”。
- 整体设计方向采用“工作台卡片式”。
- 中间区采用以下结构：
  - 顶部保留当前页标题和状态
  - 第一张大卡整合 `画面文字` 与 `画面描述`
  - 第二张卡单独承载 `AI 绘画提示词`
  - 第三张卡统一承载 `引用角色` 与 `引用场景`
- 右侧区采用以下结构：
  - 顶部主预览卡
  - 中部历史记录带
  - 下部操作卡
  - 最底部弱化的项目进度卡
- 本次“历史记录”只做 UI 骨架，优先兼容当前数据结构；若暂无真实历史数组，则展示当前图或空状态。

## 方案

### 1. 中间区总体定位

中间区从当前的纵向表单列表，改为三张主卡片组成的创作工作台：

- 内容输入卡
- 提示词编辑卡
- 素材引用卡

这样做的目标是让用户先理解“我正在做哪一类工作”，再进入具体字段输入，而不是从上到下机械浏览一串表单。

### 2. 中间区头部

保留当前页标题和状态 badge，但头部信息更收敛：

- 标题保留 `封面生成 / 第 N 页生成`
- 状态 badge 继续显示当前状态
- 说明文字缩短，避免当前较强的“说明文案感”

头部的职责只保留“告诉用户当前正在编辑什么”，不再承担大量解释性内容。

### 3. 内容输入卡

将当前分散的 `画面文字` 与 `画面内容描述` 合并到同一张大卡片中，上下分区展示：

- 上半区：`封面标题 / 画面文字`
- 下半区：`封面画面描述 / 画面内容描述`

设计原则：

- 通过同卡分区降低碎片感
- 保留字段顺序，避免用户重新学习编辑流程
- 仍保留当前 placeholder 和提示性说明，但说明长度适度收敛

这张卡的定位是“内容基础输入区”，不与提示词卡争夺视觉中心。

### 4. 提示词编辑卡

`AI 绘画提示词` 改为中间区最强视觉卡片，作为工作台核心：

- 标题为 `AI 绘画提示词`
- `重新生成 AI 绘画提示词` 按钮放在卡片头部右上角
- 错误提示保留在卡片内部，并与按钮形成明确关联
- `PromptEditor` 获得更大的可视空间和更清晰的容器边界

设计目标：

- 让用户一眼知道这里是“AI 出图的核心控制区”
- 减弱当前“像普通文本域”的感受
- 让自动生成、手动编辑、查看引用素材三类行为围绕这张卡展开

### 5. 素材引用卡

当前 `引用角色` 与 `引用场景` 两段内容，合并为一张 `引用素材` 卡片。

卡片内部仍区分两类内容，但不再拆成两个彼此独立的大区块：

- 角色引用作为一个分组
- 场景引用作为一个分组
- 各自保留缩略图、点击预览、标签名称
- 空状态文案保留，但放入卡内轻提示区

设计目标：

- 缩短页面纵向长度
- 保留角色/场景语义区分
- 提升素材区域的整体性，让它更像“提示词解析结果”而不是附加列表

### 6. 中间区视觉语言

中间区整体采用更明确的卡片层级：

- 统一使用更大圆角
- 卡片背景采用轻层叠透明度，而不是整块纯色白板
- 卡片标题区可加入轻量分组标题样式
- 提示词卡在边框、阴影或背景对比上高于其他卡片

整体方向是“专业创作工作台”，而不是“营销感 UI”或“极简表单页”。

### 7. 右侧总体定位

右侧区域从当前的“预览 + 操作堆叠侧栏”，调整为三段式：

- 主预览卡
- 历史记录带
- 操作卡

项目进度信息仍保留，但退到最底部，并降低存在感。

### 8. 主预览卡

主预览卡是右侧的第一视觉重心：

- 大图预览占据右侧主要高度
- 继续支持点击放大预览
- 在预览图表层叠加轻量信息层，展示当前页名、状态、比例
- 空状态时提供更完整的占位视觉，而不是简单图标和一句提示
- hover 时保留轻量蒙层和放大提示

设计目标：

- 当前图片成为右侧第一关注点
- 生成中、已生成、空状态都具备完整视觉语义
- 让右侧更像“当前作品面板”，而不是按钮集合

### 9. 历史记录带

在主预览卡下方增加历史记录 UI 骨架：

- 采用横向缩略图列表
- 当前项高亮
- hover 有轻微放大或边框反馈
- 生成中可以展示占位态卡片

本次边界：

- 如果当前状态结构没有真实历史版本数组，则该区域先渲染“当前图缩略卡 + 空状态说明”或兼容占位内容
- 不在本次任务中新增页面/封面的历史图片存储结构
- 不修改生成逻辑以沉淀多版本结果

这样可以先把右侧结构搭起来，为后续真实历史功能预留稳定位置。

### 10. 操作卡

将当前比例切换、生成按钮、重新生成按钮、进入编辑页按钮集中到一张操作卡：

- 比例选择仍保留
- `生成当前页插画 / 重新生成当前页` 保持主按钮
- `进入编辑页定稿` 作为次按钮保留
- 按钮层级更清晰，主次更明确

设计目标：

- 操作不与主预览争抢视觉焦点
- 用户仍能快速完成“改提示词 -> 出图 -> 定稿”的闭环

### 11. 项目进度卡

保留当前进度信息，但视觉弱化：

- 继续显示正文页生成进度
- 继续显示封面状态
- 继续显示页面定稿进度
- 满足进入下一阶段时仍保留提示

该卡只承担辅助信息展示，不再与主预览和操作卡争抢注意力。

### 12. 保留逻辑

本次不改以下逻辑：

- 页面切换逻辑
- 封面与页面 prompt 自动生成逻辑
- 手动修改 prompt 和引用素材逻辑
- 页面图片生成逻辑
- 预览弹窗逻辑
- `进入编辑页定稿` 跳转逻辑
- 页面状态计算与进度统计逻辑
- `dispatch` 行为和现有 reducer

即：本次是工作台 UI 重设计，而不是功能重构。

## 实现边界

- 主要修改文件为 `src/components/studio/stages/Stage5Pages.tsx`
- 可以在该文件内新增少量局部 UI 映射或渲染辅助变量
- 不新增后端接口
- 不修改全局状态数据结构
- 不扩展页面/封面的图片历史存储模型
- 不顺手改左侧页面目录和顶部 `StageActionHeader` 的业务行为

## 风险与处理

### 风险 1：历史记录只有 UI，没有真实数据支撑，容易显得空

处理：

- 明确本次定位为“历史区 UI 骨架”
- 使用当前图缩略卡、空状态提示和占位态保证结构成立
- 后续若增加真实历史数组，可直接挂接到这一区域

### 风险 2：中间区卡片过多，可能反而增加视觉负担

处理：

- 控制在三张主卡片内，不再继续细拆
- 将 `画面文字` 与 `画面描述` 合并到一张卡中
- 将 `引用角色` 与 `引用场景` 合并到一张卡中

### 风险 3：提示词卡强化后，其他区块可能显得过弱

处理：

- 提示词卡只强化一个层级
- 内容输入卡与素材引用卡保持统一基础卡片语言
- 通过留白和标题层次建立主次，而不是堆叠大量装饰

### 风险 4：桌面端改好后，移动端堆叠可能受到影响

处理：

- 移动端继续维持纵向堆叠思路
- 重点优化桌面端工作台呈现
- 不在本次额外引入复杂响应式交互

## 非目标

- 本次不新增真实的页面图片历史版本功能
- 本次不修改 `PromptEditor` 的业务能力
- 本次不修改页面生成规则或提示词生成规则
- 本次不重做左侧页面目录
- 本次不重做顶部阶段头部逻辑
- 本次不扩散到 `Stage2Story`、`Stage4Assets`、`Stage6Finalize`
- 本次不增加低价值自动化测试

## 验收标准

- `Stage5Pages` 中间区域从长表单重组为三张主卡片组成的工作台
- `AI 绘画提示词` 成为中间区最明显的视觉中心
- `引用角色` 与 `引用场景` 被整合进统一的素材引用卡片
- 右侧区域形成 `主预览卡 + 历史记录带 + 操作卡 + 弱化进度卡` 的结构
- 主预览图在桌面端成为右侧第一视觉焦点
- 历史记录区域即使在没有真实历史数组时也具备合理 UI 骨架
- 现有提示词生成、图片生成、预览、跳转编辑页、进度统计逻辑保持可用
- 不引入新的 TypeScript、JSX 或明显布局错误

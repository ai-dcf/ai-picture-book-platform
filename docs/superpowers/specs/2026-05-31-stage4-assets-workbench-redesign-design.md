# Stage4Assets 素材设定工作台重设计

日期：2026-05-31

## 背景

当前 `Stage4Assets.tsx` 采用顶部 tabs + 页面内纵向卡片列表的结构。随着角色、场景、提示词、预览图、历史版本等信息叠加，页面更像“长表单列表”，不够贴近桌面大屏工作台场景。

用户希望参考原型图中的布局，对素材设定页进行 UI 重设计，让角色与场景都采用更聚焦的工作台式编辑体验。

## 目标

- 让 `Stage4Assets.tsx` 更接近原型的工作台结构。
- 保留顶部 `角色设定 / 场景设定` tabs，但视觉做轻度重设计。
- 在每个 tab 内改为统一的三栏布局：
  - 左侧素材列表
  - 中间编辑面板
  - 右侧大图预览与主要操作区
- 页面底部增加当前素材的历史版本区。
- 角色与场景共享同一套页面骨架，只替换字段文案与具体行为。

## 用户已确认的规则

- 重设计范围为：`角色 + 场景都改`。
- 顶部继续保留 `角色设定 / 场景设定` tabs，不合并成单页。
- tabs 内部采用三栏布局：`左侧列表 + 中间编辑 + 右侧预览`。
- 左侧列表采用“单选切换 + 底部历史区”的交互。
- 角色与场景采用完全一致的页面骨架。
- 左侧列表只显示名称，不显示缩略图。
- 右侧预览区采用“大图优先”。
- tabs 采用轻度重设计，而不是保留现状。
- 整体方向采用“贴原型优先”。

## 方案

### 1. 页面总体结构

`Stage4Assets` 保留顶部 tabs，但每个 tab 内部从“纵向卡片列表”重组为工作台结构：

- 左侧：素材名称列表，单选当前素材
- 中间：当前素材的描述编辑与提示词编辑
- 右侧：当前素材的大图预览与主操作区
- 底部：当前素材的历史版本区

说明：

- 页面不再同时展示多个 `CharacterCard` / `SceneCard`
- 页面改为“一次只聚焦当前选中的一个素材”
- 角色 tab 和场景 tab 使用一致的三栏骨架，保证认知一致性

### 2. 顶部 tabs

- 继续保留 `角色设定` 与 `场景设定` 两个 tab。
- 视觉上做轻度重设计，使其更接近工作台一级切换，而不是普通内容页 tabs。
- 本次不把 tabs 改成新的阶段导航，也不修改其底层切换逻辑。

### 3. 左侧素材列表

- 左侧列表只显示素材名称。
- 点击列表项后，切换当前选中的角色或场景。
- 当前选中项使用更明显的高亮底色和边框状态。
- 列表不显示缩略图，不额外显示复杂状态统计。
- 当素材数量较多时，左侧列表支持独立滚动。

### 4. 中间编辑面板

中间区域只展示当前选中素材的编辑内容：

- 角色：
  - 角色形象描述
  - AI 绘画提示词
- 场景：
  - 场景描述
  - AI 绘画提示词

编辑面板采用与原型相近的“集中编辑区”形式，不再把每个素材都包成完整卡片纵向堆叠。

### 5. 右侧预览与主操作

右侧区域以大图预览为核心：

- 角色：
  - 当前角色基础形象大图
  - 生成基础形象
  - 确认基础形象
  - 比例选择
  - 状态提示
- 场景：
  - 当前场景候选图或正式版本大图
  - 生成候选图
  - 设为正式版本
  - 比例选择
  - 状态提示

原则：

- 视觉优先级先给大图，再给操作
- 操作按钮应围绕当前预览组织，而不是散落在多个卡片内部

### 6. 底部历史版本区

页面底部只展示当前选中素材的历史：

- 角色：展示当前角色的基础形象历史版本
- 场景：展示当前场景的候选图历史

历史区与左侧当前选中项联动：

- 切换左侧素材时，底部历史区同步更新
- 不再让每张卡片内部各自折叠展开历史区

### 7. 保留逻辑

本次只改页面组织方式，不改底层能力：

- 批量生成角色提示词
- 批量生成角色基础图
- 场景提示词生成
- 场景候选图生成
- 设为正式版本
- 历史版本切换
- 图片预览弹窗
- 底部“确认素材，进入逐页生成”流程
- 现有 reducer、状态结构、数据字段

### 8. 实现边界

- 只修改 `src/components/studio/stages/Stage4Assets.tsx`
- 不新增后端接口
- 不修改全局状态模型
- 不顺手改其他阶段页面
- 不要求角色与场景完全共用一个超抽象组件，但布局骨架和交互模型必须一致

## 风险与处理

- 风险：`CharacterCard` / `SceneCard` 当前封装的是“多卡列表”思路，直接复用可能导致新布局仍然带有旧卡片痕迹。
- 处理：允许在 `Stage4Assets.tsx` 内重组 UI 结构，必要时把旧卡片内部有价值的块状内容拆出来复用，而不是强行保留整个卡片。

- 风险：历史版本区从卡片内部移动到底部后，当前选中素材联动逻辑会变复杂。
- 处理：引入页面级“当前选中素材”状态，让编辑区、预览区、历史区都围绕同一选中项渲染。

- 风险：场景页包含候选图和正式图逻辑，右侧大图优先布局下需要明确展示优先级。
- 处理：优先展示当前正式版本；如果尚未设定正式版本，则展示当前候选图主视图。

## 非目标

- 本次不重做 `Stage2Story`、`Stage5Pages`、`Stage6Finalize`
- 本次不引入移动端适配
- 本次不改变素材生成规则或提示词生成规则
- 本次不对 tabs 之外的全局导航做重设计
- 本次不新增低价值自动化测试，只做定向验证

## 验收标准

- `Stage4Assets` 保留 `角色设定 / 场景设定` tabs，但每个 tab 内改为三栏工作台布局。
- 左侧列表只显示名称，并支持单选切换当前素材。
- 中间区域只编辑当前素材。
- 右侧区域以当前素材的大图预览为核心，并承载主要操作。
- 页面底部展示当前素材的历史版本区。
- 角色与场景两类页面的骨架结构保持一致。
- 原有生成、确认、选择正式版本、历史恢复与确认进入下一阶段逻辑保持可用。
- `Stage4Assets.tsx` 不引入新的 TypeScript 或 JSX 结构错误。

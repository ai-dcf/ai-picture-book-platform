# Stage5Pages 工作台布局对齐设计

日期：2026-05-31

## 背景

当前 `Stage5Pages.tsx` 已具备完整的逐页生成能力，包括：

- 左侧封面/页码切换
- 中间编辑区
- 右侧预览与生成操作
- 顶部统一的 `StageActionHeader`

但从整体视觉层级来看，页面仍偏向“把三块功能区域并排摆放”，而不是类似 `Stage2Story.tsx` 的统一工作台结构。用户明确反馈当前问题集中在：

- 顶部操作区与下方内容区之间的层级关系不够清晰
- 下方三栏内容像平铺区域，缺少一个统一的工作区容器
- 左中右三栏的主次关系不够稳定

用户希望 `Stage5Pages` 在不改变业务逻辑的前提下，整体布局语言对齐 `Stage2Story`。

## 目标

- 让 `Stage5Pages.tsx` 的页面骨架对齐 `Stage2Story.tsx` 的工作台结构。
- 保留现有逐页生成逻辑、状态计算、按钮行为与表单字段。
- 重点修正视觉层级、留白、容器边界、左右工作区关系。
- 让页面优先呈现为“工作台”，再呈现为“表单与操作集合”。

## 用户已确认的规则

- 问题重点是“顶部操作区和内容区之间层级/留白不协调”。
- 希望 `Stage5Pages` 整体像 `Stage2Story`，而不是只修补某个局部间距。
- 对齐范围包含：
  - 外层整体骨架
  - 左中右三栏关系
  - 统一工作台容器感
- 本次只做 UI 布局与容器层级修正，不改业务逻辑。

## 方案

### 1. 页面总体骨架

保留顶部 `StageActionHeader`，下方主内容区改为一个统一的大工作台容器，结构对齐 `Stage2Story`：

- 顶部：阶段级操作头部
- 下方：单一主工作台容器
- 工作台内部：左导航、中编辑、右预览三栏

目标效果：

- 顶部头部与正文区有清晰分层
- 正文区整体成为一块独立的工作台
- 视觉上避免三栏直接裸露平铺

### 2. 外层工作台容器

参考 `Stage2Story` 的做法，`Stage5Pages` 的下方内容统一包裹在一个大容器中：

- 使用统一圆角、边框和背景
- 在容器内部再划分左、中、右三栏
- 主容器承担“内容工作区”的整体边界

这样可以把当前“页面根层直接平铺三栏”的组织方式，调整为“卡片内三栏工作区”。

### 3. 左侧导航栏

左栏从当前较窄、较弱的列表栏，调整为更明确的导航区：

- 语义上作为“页面目录”
- 视觉上采用独立卡片或 sticky 导航块
- 保留封面与页码切换逻辑
- 提升宽度与标题区存在感，让它更接近 `Stage2Story` 的左侧目录区

左栏的目标不是承载大量信息，而是提供稳定的页面切换入口和当前页高亮状态。

### 4. 中间主编辑区

中栏作为页面主工作区，承担主要输入与编辑任务：

- 页标题和状态 badge 保留，但纳入中栏自己的 header
- 编辑表单继续按现有顺序保留：
  - 画面文字/封面标题
  - 画面内容描述
  - AI 绘画提示词
  - 引用角色
  - 引用场景
- 中栏内部使用独立滚动区域
- 中栏外层拥有完整边框、圆角和背景承载

这样可以让用户的视觉焦点明确落在中间，而不是被三栏平均分散。

### 5. 右侧预览区

右栏定位为辅助预览与主要生成操作区：

- 顶部保留“封面插画 / 本页插画”标题
- 中间保留大图预览区域
- 下方保留比例选择、生成按钮、进入编辑页按钮和进度摘要
- 右栏作为独立侧栏卡片，不再只是与中栏等权的普通列容器

目标是让右栏在视觉上稳定地承担“看结果 + 做生成动作”的职责。

### 6. 滚动与高度策略

对齐 `Stage2Story` 的策略，滚动主要发生在中栏内容区：

- 桌面端整体页面保持稳定高度
- 左栏列表可独立滚动
- 中栏表单区可独立滚动
- 右栏尽量保持完整信息块，不与中栏共享滚动语义

这样可以减少“整页滚动 + 局部滚动”混杂带来的层级混乱。

### 7. 保留逻辑

本次不改以下能力：

- 页面切换逻辑
- 封面与页面 prompt 自动生成逻辑
- 页面图片生成逻辑
- 预览弹窗
- 进度统计与状态展示
- 页面字段编辑与 `dispatch` 行为
- `StageActionHeader` 的接入方式

即：本次只重组容器和布局，不修改功能语义。

## 实现边界

- 只修改 `src/components/studio/stages/Stage5Pages.tsx`
- 不新增后端接口
- 不修改 reducer、数据结构和 hook
- 不把本次布局调整扩散到其他阶段页面
- 可以基于当前未提交的本地改动继续演进，但不得回退用户现有改动

## 风险与处理

### 风险 1：现有三栏容器直接改 class 后仍保留“平铺感”

处理：

- 不只微调间距，直接把下方内容改成“统一工作台容器 + 内部分栏”的层级
- 必要时增加一层包裹容器，而不是只调宽度

### 风险 2：移动端堆叠布局被桌面端重构影响

处理：

- 移动端仍保持纵向堆叠
- 重点优化桌面端的大屏工作台布局
- 不额外引入复杂的移动端交互变化

### 风险 3：中栏和右栏都滚动导致体验不稳定

处理：

- 明确中栏承担主要滚动
- 右栏尽量作为稳定侧栏内容
- 左栏滚动只用于页码列表过长场景

## 非目标

- 本次不修改字段顺序或业务逻辑
- 本次不重做 `PromptEditor`
- 本次不改 `Stage2Story`、`Stage4Assets`、`Stage6Finalize`
- 本次不新增复杂响应式交互
- 本次不新增低价值自动化测试

## 验收标准

- `Stage5Pages` 顶部 `StageActionHeader` 与下方内容区层级清晰分离
- 下方内容区形成统一的大工作台容器，而不是三块平铺区域
- 桌面端呈现稳定的 `左导航 / 中编辑 / 右预览` 三栏关系
- 左栏更接近“页面目录”，中栏更像主编辑区，右栏更像预览与操作侧栏
- 页面整体视觉语言与 `Stage2Story` 更一致
- 不引入新的 TypeScript、JSX 或布局结构错误
